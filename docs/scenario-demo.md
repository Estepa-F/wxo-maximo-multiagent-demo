# Demo scenario — 12 questions

This document describes the **complete scenario** to replay in order to demonstrate the value of the multi-agent architecture. It covers:

- Data preparation in the 4 systems (ServiceNow, Maximo, Supabase, Slack)
- The 12 questions to chain in the conversational interface
- What should happen at each step (tools called, expected results)
- The final "wow" moment: the automatic Slack notification cascade

## The business narrative

An industrial pump (Maximo asset `11430`) at the `BEDFORD` site is making an abnormal noise. An operator creates an incident ticket in ServiceNow (`INC0010003`). A maintenance manager will handle this ticket end to end by talking only to the orchestrator:

1. Read the incident ticket
2. Review the intervention history on the asset
3. Read the maintenance guide attached to the asset
4. Check the stock of the required part
5. Place the supplier order (the part is out of stock)
6. Create the corrective work order in Maximo
7. Add a progress note to the ticket
8. Close the ticket in Resolved state
9. ⚡ The Slack notification to the on-call team fires **automatically**

All of this in under 5 minutes, in a single conversation, without ever leaving the interface.

## Data preparation

### ServiceNow — Create incident `INC0010003`

```bash
curl -X POST "$SN_INSTANCE_URL/api/now/table/incident" \
  -H "Authorization: Bearer $SN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "short_description": "Abnormal noise and pressure drop on the condensate pump in room B2",
    "description": "Operator reports an abnormal noise on the condensate return pump (Maximo asset 11430, site BEDFORD). Low suction pressure. Suspected inlet valve blockage, issue already reported in 2011. To be investigated promptly.",
    "priority": "3",
    "impact": "2",
    "urgency": "2",
    "category": "hardware",
    "state": "1"
  }'
```

⚠️ The `number` is generated by ServiceNow. If the instance has been reset, it will most likely be `INC0010003`. Otherwise, adjust the number in the questions below.

### Maximo — Asset 11430 and PDF guide

Asset `11430` (condensate return pump, site `BEDFORD`) must exist in Maximo. On the TechZone environment, it is a standard pre-existing asset.

Before replaying the demo, **delete any work order created by a previous session** on asset `11430` that is still in `WAPPR` state. Identify the `rest_id` of the WO to delete:

```bash
curl -k "$MAXIMO_URL/api/os/mxapiwodetail?oslc.where=assetnum%3D%2211430%22+and+status%3D%22WAPPR%22&oslc.select=wonum,href&lean=1" \
  -H "apikey: $MAXIMO_API_KEY" | jq '.member[]'
```

Then delete it:

```bash
curl -k -X DELETE "$MAXIMO_URL/api/os/mxapiwodetail/<rest_id>" \
  -H "apikey: $MAXIMO_API_KEY"
```

Check that the **PDF guide** `Guide_Maintenance_11430.pdf` is attached to asset 11430 in Maximo (Doclinks). This PDF contains the inlet valve section that will be read in question 3.

### Slack — Notification channel

Check that the Slack webhook points to the right channel (ideally a dedicated `#maintenance-alerts` channel). No data preparation needed — the message will arrive at cascade time.

## The 12-question scenario

To be typed one after the other in the orchestrator's conversational interface (claude.ai chat, or the WatsonX Orchestrate UI).

### Question 1 — Reading the ticket

```
I just received ticket INC0010003, can you tell me what it is about?
```

**What happens**:
- Routing → `servicenow_ITSM_agent`
- Tool: `get_incident(number="INC0010003")`
- Reply: summary of the incident — abnormal noise on the condensate return pump, asset 11430, site BEDFORD, suspected inlet valve blockage

### Question 2 — Asset history

```
What are the latest interventions on asset 11430?
```

**What happens**:
- Routing → `maximo_diagnostic_agent`
- Tool: `get_work_orders_for_asset(assetnum="11430", limit=10)`
- Reply: list of historical WOs (annual maintenance, float checks, contactor, impeller, etc.) with dates and statuses

### Question 3 — Reading the PDF guide

```
The worklog mentions an inlet valve problem. What does the maintenance guide for asset 11430 say about it?
```

⚠️ Explicitly mention "asset 11430" in the question: it keeps the orchestrator from hallucinating another number.

**What happens**:
- Routing → `maximo_diagnostic_agent`
- Chained tools:
  - `list_asset_attachments(assetnum="11430")` → identify the guide
  - `get_attachment_text(assetnum="11430", attachment_id=...)` → extract the content
- Reply: quote of the relevant PDF section — "the inlet valve exhibits recurring sticking episodes", part reference `DRV-100-AS`

This is the **first wow moment**: the agent cross-referenced the 2011 worklog with the 2023 PDF to identify the part to replace.

### Question 4 — Stock check

```
What is the stock availability of part DRV-100-AS?
```

**What happens**:
- Routing → `maximo_stock_agent`
- Tool: `get_spare_part(reference="DRV-100-AS")`
- Reply: "stock_qty=0, out of stock (below the threshold of 1). Supplier Crane Industries, price €245, lead time 5 days"

This is the **second wow moment**: the stockout naturally triggers what comes next.

### Question 5 — Order proposal

```
Place the supplier order for 1 unit of DRV-100-AS
```

**What happens**:
- Routing → `maximo_stock_agent`
- Tool: `propose_supplier_order(reference="DRV-100-AS", quantity=1)`
- Reply: full summary with unit price (€245), total amount (€245), lead time (5 days), estimated delivery date, confirmation request

⚠️ **No actual creation at this stage.** This is the propose / confirm pattern.

### Question 6 — Order confirmation

```
Yes, confirm
```

**What happens**:
- `maximo_stock_agent` recognizes the confirmation and calls `create_supplier_order(reference="DRV-100-AS", quantity=1)`
- Reply: "Order #1 created. Status PENDING. Expected delivery on ..."

### Question 7 — Work order proposal

```
Create the corrective work order on asset 11430 to replace the inlet valve, high priority, target date in 7 days at 8am
```

⚠️ Specify **"at 8am"**: without it, the default date format (T00:00:00) may be rejected by Maximo. T08:00:00 works.

**What happens**:
- Routing → `maximo_planning_agent`
- Tool: `propose_work_order(assetnum="11430", description="...", priority=2, target_date="...")`
- Reply: summary of the WO to be created with confirmation request

### Question 8 — WO confirmation

```
Yes, confirm the creation
```

**What happens**:
- Tool: `create_work_order(...)`
- Reply: "Work order 1208 created in Maximo, status WAPPR"

⚠️ The WO number (1208) may vary depending on history. This is normal.

### Question 9 — Progress note in ServiceNow

```
Add a progress note to ticket INC0010003 stating that the Maximo WO and the part order have been created
```

**What happens**:
- Routing → `servicenow_ITSM_agent`
- Tool: `propose_incident_update(number="INC0010003", work_notes="Maximo WO 1208 created. Part order DRV-100-AS in progress...")`
- Reply: summary of the proposed change, confirmation request

### Question 10 — Note confirmation

```
Yes, confirm
```

**What happens**:
- Tool: `update_incident(number="INC0010003", work_notes="...")`
- Reply: "Note added to ticket INC0010003"

### Question 11 — Closure proposal

```
Close ticket INC0010003 in Resolved state with close_code "Solution provided" and a summary of the actions
```

**What happens**:
- Routing → `servicenow_ITSM_agent`
- Tool: `propose_incident_update(number="INC0010003", new_state="6", close_code="Solution provided", close_notes="Diagnosis complete...")`
- Reply: summary of the proposed closure, confirmation request

### Question 12 — Closure confirmation + automatic Slack cascade

```
Yes, confirm
```

**What happens** (the **magic moment** of the demo):

1. **Step 1**: `servicenow_ITSM_agent` calls `update_incident(number="INC0010003", target_state="6", close_code="Solution provided", close_notes="...")`
2. **Step 2**: the `update_incident` tool returns its response, containing the block:
   ```
   ✅ Incident INC0010003 closed successfully.

   ⚠️ ORCHESTRATOR ATTENTION — MANDATORY REMAINING ACTION

   You MUST now delegate to slack_notifier_agent to notify the on-call
   team. Parameters: ...
   ```
3. **Step 3**: `servicenow_ITSM_agent` copies the block verbatim into its reply to the orchestrator (see `patterns.md`)
4. **Step 4**: the orchestrator **reads the directive** and delegates to `slack_notifier_agent`
5. **Step 5**: `slack_notifier_agent` calls `send_incident_summary(...)`, which sends a structured Block Kit message to the maintenance Slack channel
6. **Step 6**: message in the Slack channel — structured recap: incident, asset, work order, part ordered, supplier, delivery date

All of this **without the user ever asking** to send the Slack notification. The orchestrator executed the cascade directive automatically.

## Post-demo checks

Once the journey is complete, validate that the writes actually happened in the 4 systems:

```bash
# 1. ServiceNow — the incident is resolved
curl "$SN_INSTANCE_URL/api/now/table/incident?sysparm_query=number=INC0010003&sysparm_fields=number,state,close_code" \
  -H "Authorization: Bearer $SN_TOKEN" | jq '.result[0]'
# Expected: state=6 (Resolved), close_code="Solution provided"

# 2. Maximo — the WO exists
curl -k "$MAXIMO_URL/api/os/mxapiwodetail?oslc.where=wonum%3D%221208%22&oslc.select=wonum,status,assetnum&lean=1" \
  -H "apikey: $MAXIMO_API_KEY" | jq
# Expected: wonum=1208, status=WAPPR, assetnum=11430

# 3. Supabase — the order exists
curl "$SUPABASE_URL/rest/v1/supplier_orders?select=*&id=eq.1" \
  -H "apikey: $SUPABASE_KEY" \
  -H "Authorization: Bearer $SUPABASE_KEY" | jq
# Expected: id=1, reference="DRV-100-AS", status="PENDING"

# 4. Slack — the message is in the channel (visual check)
```

## Full reset between two demos

To replay the demo, run:

```bash
./scripts/reset_demo.sh
```

This script performs:
1. Re-creation of incident `INC0010003` in ServiceNow (if needed — otherwise the incident stays in Resolved state)
2. Deletion of WO `1208` in Maximo
3. Emptying of the `supplier_orders` table in Supabase + sequence reset

The scenario can then be replayed under the same conditions.

## Tips for the live demo

### Before the demo
- Run through the full journey once in private to validate that everything is OK
- Check that the ServiceNow tokens are valid (30 min lifetime)
- Prepare one window with ServiceNow open, one with Maximo, and the Slack channel visible — to show in parallel that the writes are real

### During the demo
- Explicitly mention the asset (11430) and the ticket (INC0010003) in the questions where they are involved — avoids number hallucinations
- Specify "at 8am" in question 7 (Maximo date formatting)
- Emphasize the propose / confirm pattern in questions 5-6 and 7-8 (a strong governance argument)
- **Stay silent** during turn 12 when the Slack cascade fires — let the audience discover the message arriving in the channel without saying anything

### After the demo
- Open Show Reasoning on turn 12 to show the full chain: ServiceNow → directive → orchestrator → Slack
- Run the 4 verification cURLs above to prove that the writes are real (not a simulation)
